## 一、托管平台选择

| 平台 | 是否需要账号 | 国内速度 | 适用建议 |
|---|---|---|---|
| **Gitee（码云）** | 需要 Gitee 账号 | 快 | 上手最简单，国内首选 |
| **华为云 CodeArts Repo** | 需要华为云账号（≠开发者论坛账号） | 快 | 已在用华为生态、想用制品管理/工单时 |
| **GitHub** | 需要 GitHub 账号 | 慢、可能要代理 | 全球共享、教程/社区多、海外用户多 |

- 各平台账号互不通用，`push` 那一步需要对应平台账号。
- 华为开发者**论坛**、**CSDN** 不是代码托管平台（不能托管源码），只能做展示/引流。

## 二、新建仓库（发布流程）

1. **建 `.gitignore`**（项目根目录），忽略 Godot 缓存与导出产物：
   ```gitignore
   .godot/
   *.pck
   *.exe
   *.apk
   *.aab
   *.jks
   *.keystore
   .DS_Store
   Thumbs.db
   ```
   > 注意：源码旁的 `*.wav.import` 要提交（是资源的一部分）；`.godot/` 是编辑器缓存要忽略。`audio/*_bak/` 备份音频按需决定，可加忽略。

2. **本地初始化与首次提交**：
   ```bash
   cd D:\Godot\projects\my-kalimba
   git init
   git add .
   git commit -m "init: 拇指琴教学应用"
   ```

3. **在平台新建远程仓库**（GitHub / Gitee / CodeArts），**不要勾选自动生成 README**。

4. **关联并推送**：
   ```bash
   git remote add origin <远程仓库地址.git>
   git branch -M main
   git push -u origin main
   ```

> 「上传代码仓库」只需要 **git 版本管理**，**不需要签名**。签名分两类，都和"传源码"无关：
> - 提交签名（GPG/SSH commit signing）：自愿可选。
> - Android 打包签名（keystore/jks）：发布 App 时才需要。

## 三、多人协作

核心：**一点提交（`main`）+ 分支协作 + MR/PR 评审**。

- 协作者 `clone` / `fork` 仓库 → 各开功能分支：
  ```bash
  git checkout -b feat/add-foo
  git add . && git commit -m "新增功能"
  git push -u origin feat/add-foo
  ```
- 走 **Pull Request（PR）/ Merge Request（MR）** 请求合入 `main` → 评审通过 → 合并。
- **先拉后推**：动手前 `git pull origin main`；合回前 `git merge main` 降低冲突。
- **冲突**：两人改同一文件同一处会冲突，手动解决 → `git add` → `commit`。

> Godot 专属提醒：`.godot/` 不要提交；协作者尽量用**相同 Godot 版本 + 相同导出设置**，避免场景/缓存冲突。

## 四、权限与评审（治理模型）

- **谁来设权限**：仅**仓库 Owner** 及 Owner 指派的管理员（Admin/Maintainer）能设置。
- **设什么**：成员授权（开发者/管理者/只读）、「分支保护」、`main` 禁止直接 push、合并权限、默认评审人。
- **谁来评审**：通常任何有 `main` 读权限的成员可被指定 **Reviewer**；合并到**保护分支**时必须走 MR 且至少 1 人 Approved。

| 平台 | 设权限者 | 评审角色 |
|---|---|---|
| CodeArts Repo | 仓库/项目管理员 | 合并请求里指定 Reviewers |
| Gitee | 仓库管理员 | 指派 Reviewers + 「要求≥N 人评审」 |
| GitHub | Owner + 授权 Maintainer | Reviewers / CODEOWNERS |

> 最小实践：`main` 保护、禁止直接推、改动必须走 MR + 1 人 Approved。

## 五、发布 Release

1. 打版本标签：
   ```bash
   git tag v1.0.0
   git push origin v1.0.0
   ```
2. 新建 Release（仓库页面 → Releases → New Release）：
   - 填版本号 `v1.0.0`、标题、更新说明（Release Notes）。
   - **上传产物/安装包**：Android `apk/aab` 或桌面 `exe/zip`（CodeArts/Gitee/GitHub 都支持附件，大文件另放对象存储）。
3. 命名建议 `v主.次.修订`，与 git tag 一致。

## 六、收集软件评测意见

| 渠道 | 角色 | 适合 |
|---|---|---|
| **CSDN** | 开发教程 + 项目展示 + 引流 | 程序员/技术曝光、文档化 |
| **B 站** | 试弹视频 + 评论区真实反馈 | **目标用户**专业评测（音准、手感、教学编排） |
| **拇指琴贴吧 / 豆瓣小组** | 琴友试用打卡 | 垂直琴友圈 |
| **小红书 / 知乎**（乐器话题）| 图文测评 + 试用 | 泛音乐用户 |
| **Reddit** r/kalimba 等 | 海外卡林巴讨论 | 海外用户 |
| **GitHub / Gitee Issues** | 统一收集意见清单 | 可追踪、专业工单 |

**收集意见的正确姿势**：
- 提供**可直接运行/试玩的版本**（apk/aab/网页版），别只发源码。
- 给**明确试用任务**（弹某段、试三个音色、反馈手指映射是否顺、练习模式指引是否清晰）。
- 留**反馈渠道**（Issues / 问卷）。

**推荐组合拳**：
1. CSDN 发开发教程 + 仓库链接（技术曝光）；
2. B 站 + 拇指琴贴吧发试弹视频（目标用户专业评测）；
3. Issues 统一收集中文反馈，形成可追踪清单。
